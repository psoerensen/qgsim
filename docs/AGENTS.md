# AGENTS.md

## Project purpose

This repository contains `qgsim`, a small R teaching package for
quantitative genetics and breeding-simulation examples.

The package currently focuses on two ideas:

1.  Simulating simple multi-generational pedigrees.
2.  Demonstrating gene dropping from parental haplotypes using
    interchangeable R, C++, and Fortran implementations.

The package is intentionally small and educational. Do not describe it
as a complete production breeding simulator.

## Current exported functionality

The current main user-facing functions are:

- [`simulate_pedigree()`](https://psoerensen.github.io/qgsim/reference/simulate_pedigree.md)
- [`gene_drop_generation()`](https://psoerensen.github.io/qgsim/reference/gene_drop_generation.md)

### `simulate_pedigree()`

[`simulate_pedigree()`](https://psoerensen.github.io/qgsim/reference/simulate_pedigree.md)
simulates a simple multi-generational pedigree.

It returns a data frame with:

- `id`
- `sire`
- `dam`
- `generation`
- `sex`

Founder parents are represented by `NA`.

### `gene_drop_generation()`

[`gene_drop_generation()`](https://psoerensen.github.io/qgsim/reference/gene_drop_generation.md)
simulates marker inheritance for one generation from parental haplotypes
and a mating design.

It supports:

- `engine = "R"`
- `engine = "C++"`
- `engine = "Fortran"`

The R code handles validation, random event generation, and the
user-facing interface.

The C++ and Fortran code implement the deterministic marker-level
inheritance loop.

For the same seed, the R, C++, and Fortran engines should produce
identical outputs.

The implementation is a simple single-chromosome teaching example. It is
not a full production gene-dropping simulator.

## Native-code rules

The package now contains compiled-code examples under `src/`.

Native code currently supports the C++ and Fortran engines in
[`gene_drop_generation()`](https://psoerensen.github.io/qgsim/reference/gene_drop_generation.md).

When modifying native code:

- Be conservative.
- Keep the R, C++, and Fortran engines numerically consistent.
- Do not generate random numbers inside C++ or Fortran.
- Random events should be generated in R and passed to compiled code.
- C++ and Fortran should implement deterministic marker-level
  inheritance loops.
- Preserve native routine registration in `src/init.c`.
- Do not change [`.Call()`](https://rdrr.io/r/base/CallExternal.html) or
  [`.Fortran()`](https://rdrr.io/r/base/Foreign.html) interfaces without
  updating R wrappers and tests.
- Do not add OpenMP or external shared-library machinery unless
  explicitly asked.
- Do not commit generated native artifacts such as `.o`, `.obj`, `.dll`,
  `.so`, `.dylib`, `.lib`, or `.exe`.

## Scientific and modelling rules

- Do not invent simulation results, benchmarking claims, or performance
  claims.
- Do not describe `qgsim` as a complete breeding-scheme simulator.
- State clearly when examples are simplified teaching examples.
- [`simulate_pedigree()`](https://psoerensen.github.io/qgsim/reference/simulate_pedigree.md)
  is a simple random pedigree simulation.
- [`gene_drop_generation()`](https://psoerensen.github.io/qgsim/reference/gene_drop_generation.md)
  is a simple single-chromosome gene-dropping implementation.
- Avoid adding biological complexity without tests and clear
  documentation.
- Keep terminology consistent: pedigree, sire, dam, generation,
  haplotype, genotype, map, recombination.
